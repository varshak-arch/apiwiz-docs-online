After you create an index, it appears in the **Index** dropdown menu at the top of the left navigation panel. Use this dropdown to select an index and view its ingested logs.

# Select an index

To select an index, follow these steps:

1. Select the **Index** dropdown.
1. Select the index you want to analyze from the list.
  ![](https://admin.apiwiz.io/api/guides/images/6a6b222869d1ae970572a573)

The selected index loads its ingested logs for analysis.

![](https://admin.apiwiz.io/api/guides/images/6a6c6be569d1ae970572b6d1)

## Viewing application logs

The **Application Logs** page lets you view and analyze application log events. It displays detailed information about individual application events captured from integrated services. Each row in the table represents a single log entry generated by an application. Use this view to monitor runtime activities, analyze system behavior, and troubleshoot issues by examining log records in real time.

Application logs are captured and stored chronologically. Filtering relies on LogQL queries across three automatic metadata labels: service name/category, application name/type, and log type.

The logs table displays detailed information for each application log event.

**Event Time: **The date and time the log event was generated, used to trace event timing, correlate activity across services, and investigate issues within a time range. Example: `Jul 29, 14:49:55.921`

**Type: **The severity level assigned to the log event.

**App Name**

The application or service that generated the log event, used to identify and compare activity across applications. Examples: payment\_service, user\_service, notification\_service

**App Type**

The technology or category of the application that generated the log event, used to group and filter logs by runtime or platform. Examples: Java, .NET, Node.js, Microservice, Gateway, WSO2

**Content**

The log message generated by the application, covering events, request/response details, exceptions, and diagnostic information. Used to investigate failures and analyze application behavior. Example: Database connection failed: Connection timeout after 30 seconds

## Viewing log distribution

The **Log Distribution** chart provides a visual overview of log activity for the selected time range. It groups log events by severity level, making it easier to identify trends and monitor activity over time.

The chart displays log counts for the following severity levels:

- Error
- Info
- Warnings
- Debug
- None

Each colored bar represents the number of log events generated during a specific time interval. For example, the chart lets you compare the exact number of Error logs against Debug logs generated at a specific timestamp, such as 5:15 PM.

Use the Log Distribution chart to:

- Monitor the volume of log events over time.
- Identify spikes in specific log severity levels, such as Error or Warning.
- Compare the distribution of different log levels within the selected time range.
- Correlate log activity with the entries displayed in the logs table below.
- Isolate the timeframe of an incident, so you can narrow LogQL search queries to that window instead of querying across broad timeframes.

The chart updates automatically when you change the selected time range or execute a new query.
