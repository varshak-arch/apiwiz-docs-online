This quickstart walks you through the end-to-end process for creating a ruleset and using it to lint an API specification.

1. [Create a category](/plan-and-design/api-linting/category/): In the API Linting page, create a category to organize related rulesets.
1. [Create a ruleset](/plan-and-design/api-linting/rulesets/): Create a ruleset under the category and select the specification type: **OAS 3.0**, **AsyncAPI**, or **Data Dictionary**. Build the ruleset from scratch, or import an existing one.
1. [Create rules](/plan-and-design/api-linting/rule/): Add rules to the ruleset by selecting a rule type, defining the object path, and configuring validation details such as severity and operation.
1. [Associate specifications](/plan-and-design/api-linting/linking-an-oas-to-a-ruleset/): Link one or more API specifications to the ruleset. Available specifications and selection options depend on the specification type.
1. [Lint a specification](/plan-and-design/api-linting/executing-linting/): Run the ruleset against the API specifications, revisions, or data models you want to validate.
1. [View reports](/plan-and-design/api-linting/viewing-insights-after-executing-linting/): Review the results in the **Reports** section, including errors, warnings, informational messages, and linting activity.

Your ruleset is configured and associated with the required API specifications. You can execute linting on the selected specifications and review the results in the **Reports** section.
