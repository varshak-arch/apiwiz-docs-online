---
title: "Category"
---

A category in API Linting organizes rules based on organizational or team-specific standards and functional requirements. It groups related rules so that API validations are applied consistently.

Organizations can create custom categories based on internal guidelines, compliance requirements, or development practices. For example, you can create categories for sectors such as Banking or Healthcare, each with its own standards and API governance practices.

Categories help you:

- Structure rules logically.
- Apply organizational and sector-specific validation rules.
- Apply standards consistently.
- Maintain separation between organizational domains.
- Simplify rule management, maintenance, and auditing of API quality standards.
- Define the severity level of each rule based on business impact.

Using categories helps keep API linting consistent, scalable, and aligned with industry-specific requirements.

# Create your first category

When you open the API Linting module for the first time, the onboarding page prompts you to create a category. A category is the starting point for organizing rulesets and rules, and you must create at least one before you can create rulesets and configure API linting.

To create your first category:

1. In the API Linting module, enter a name in the **Name** field.
1. Select **Create**.
  ![](https://admin.apiwiz.io/api/guides/images/6a7afabeeb3c9603a6c45d6a)

The category is created.

# Create an additional category

Create additional categories to organize rule sets by business domain, compliance requirement, or organizational standard.

To create an additional category:

1. In the **Category** section, select **\+**.
  ![](https://admin.apiwiz.io/api/guides/images/6a7b1760eb3c9603a6c4644e)
1. Enter a name in the **Name** field.
1. Select **Create**.

The category is added to the **Category** section.
