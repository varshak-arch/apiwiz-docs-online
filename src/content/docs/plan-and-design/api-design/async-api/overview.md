AsyncAPI \(Asynchronous API Specification\) is designed for event-driven and message-based systems where communication does not follow the traditional request-response model. Instead of waiting for immediate responses, systems exchange messages or events asynchronously, enabling better decoupling, flexibility, and scalability, especially when real-time responses are not required.

### AsyncAPI and OpenAPI

While OAS defines synchronous, HTTP-based APIs, AsyncAPI serves as its counterpart for asynchronous communication. It extends API modeling to cover patterns such as publish-subscribe, event streams, and message queues, helping developers understand and work with asynchronous systems.

### Protocol support and use cases

AsyncAPI supports a wider range of protocols than OAS, including MQTT, AMQP, and WebSockets, in addition to HTTP-related patterns. This makes it suitable for the following use cases:

- Event-driven architectures
- IoT applications
- Microservices-based systems
- Messaging and streaming platforms

### AsyncAPI in event-driven architectures

AsyncAPI fits naturally into event-driven architectures, where systems react to events that indicate state changes or actions. It standardizes how events are produced, consumed, and transmitted across channels, making complex event-driven systems easier to design, build, and maintain.

AsyncAPI provides a standardized, protocol-flexible framework for modeling asynchronous APIs. With support for documentation, code generation, and testing, it enables teams to build scalable, reliable, and interoperable event-driven systems.
