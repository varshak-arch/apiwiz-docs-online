The APIwiz Developer Portal \(Dev Portal\) is an API Marketplace; a platform where your organization publishes APIs, documentation, and packages so that external developers and partners can discover, subscribe to, and consume them. 

## **Purpose**

The Marketplace acts as a bridge between API producers and their external partners. It provides a clean, public-facing directory of available APIs without exposing the internal platform, establishing a clear boundary between internal teams who build and manage APIs and external partners who consume them.

## **Key benefits**

- **API discovery and reference:** View the structure of published APIs and use them as a reference for building client-side applications.
- **Self-service package subscriptions:** Browse and subscribe to grouped API bundles directly from the Packages tab.
- **Seamless application integration:** Create applications, link them to active subscriptions, and automatically generate the credentials needed to invoke endpoints.
- **Clear separation of concerns:** Internal environments remain secure and separate from the consumer-facing portal.

## **How the Marketplace works**

The Dev Portal serves two types of users:

- **Producers**: Admins and internal teams who add, edit, and manage the APIs, documentation, and packages available on the Marketplace. Producers access these controls via **Site Administration**, available from the dropdown in the Consumer Side interface. Producers typically work with: Manage Portal, Manage Gateway, Users, Use Cases, SDKs, Events, App Approval, Settings.

![](https://admin.apiwiz.io/api/guides/images/6a61bdee69d1ae9705721da8)

- **Consumers**: External developers and partners who discover, subscribe to, and use the published APIs. Consumers typically work with: Headers, Apps, Subscriptions, My Profile, Invoices, Contact Us, Enquiries.

![](https://admin.apiwiz.io/api/guides/images/6a61bd2669d1ae9705721cfb)

Everything a producer configures is reflected in what a consumer sees and uses. As you go through this documentation, each page's content will make clear whether it describes a producer task \(configuring and managing\) or a consumer task \(discovering and using\).
