Every OpenAPI Specification \(OAS\) in APIwiz progresses through a defined set of lifecycle states, from initial design to retirement. These states help teams manage, govern, and track the progress of an API specification across its entire lifespan.

Understanding the lifecycle states ensures that the right actions are taken at each stage, such as submitting for review, publishing for consumption, or retiring an outdated specification.

#### Typical lifecycle flow

An OAS typically progresses through the following stages:

**Draft → Review → Approved → Published → Deprecated → Retired**

If reviewers identify issues during the **Review** stage, the OAS moves to **Changes Required** before returning to **Review**. If validation or compliance errors are detected at any stage, the OAS enters the **Error** state until the issues are resolved.
